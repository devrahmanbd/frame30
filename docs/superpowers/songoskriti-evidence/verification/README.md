### Caveats you need when reading them

1. **`metas=1` counts only `meta[name="csp-nonce"]`.** The post-deploy probe
   used a `name=` regex. A real document carries **two** mirrors with the same
   value: the server gate's `<meta name="csp-nonce">` (`src/server.ts:341`) and
   TanStack's `<meta property="csp-nonce">`. The committed
   `scripts/verify-live-visual.mjs` asserts **both**, the CSP response-header
   nonce, and every `nonce=` on `<script>`.
2. **There is no `x-csp-nonce` *response* header.** `src/server.ts:1047` mints
   the value on the **request** so SSR can resolve it; the response-side
   authority is the `content-security-policy` header's `'nonce-…'`. The live
   script therefore treats the CSP header as authoritative and additionally
   checks `x-csp-nonce` only if a deployment exposes it.
3. **`HEAD` on HTML returns 500** (`/theme-preview/songoskriti`): pre-existing,
   diagnosed in `postdeploy-live-verify.log` — the CSP-nonce injector pipes
   the body (`src/server.ts:176`, introduced by `da8396c2`), and a HEAD has no
   body to pipe. `GET` is 200. Carried forward as a residual, not a regression.
4. **Screenshots show the throwaway demo store and the theme preview**, never
   a production merchant's data. No credentials, keys or tokens are stored
   here (the stack's env file lives outside the repo).
