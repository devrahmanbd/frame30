# 03 — Storefront: Internationalization (i18n)

Status: Planning · Approved plan (parent: `03-storefront/README.md`) · Slice S2/S3
Owners: Storefront Platform + Editor (translation surfaces)
References: `03-storefront/README.md` (theme runtime, `lang="bn"`, a11y, cache notes) · `04-builder/theme-runtime.md` (TR-1 template = self-contained package, manifest) · `16-product-pricing/README.md` (entitlements) · `00-meta/design-system.md` §1, §3, §10 · `05-marketing/content-cms.md` (seo_meta Bangla-first conventions)
Design decision (approved): **two catalogs per store** — a _theme catalog_ (shipped by the template, source of truth for its own strings) and a _merchant catalog_ (per-merchant overrides); **locale resolution is explicit**, with a documented fallback clock; **every locale has its own published state** so drafts never leak to visitors. Storefront renders `lang="bn"` by default; both `bn` (default) and `en` are always on in v0.

---

## 1. Purpose

Bangladesh-first commerce means the storefront speaks Bangla first, English second. This plan wires the theme runtime and editor to i18n without touching the store's data model: translated copy lives in catalogs, resolution has a deterministic fallback chain, and the 60s edge cache is never served cross-locale.

## 2. Locale model & catalogs

```
locale: bn | en            (v0)
catalog levels:
  theme catalog   c/{theme_id}/{locale}.json   (from theme package; read-only per theme version)
  merchant        c/{merchant_id}/{locale}.json — overrides, tenant-scoped RLS
```

- A string is a key: `nav.home`, `cart.title`, `checkout.vat_line`, `product.buy_box`. The key is the contract; editors see values.
- **Theme catalog** ships in the theme package (manifest files come with the theme build; runtime reads them). Merchants never edit theme files — see §3 override rules.
- **Merchant catalog** holds overrides + `custom_*` keys; every override row stores `source_key`, `locale`, `value`, `draft_value`, `state` (draft/published).

## 3. Fallback clock & resolution

1. `merchant override (published)`
2. `theme catalog`
3. `platform defaults` (en) — an unpublished override counts as **missing** (it owns the key, so the theme catalog must already cover it or the platform default shows; an unpublished override never punches a hole where the theme catalog had copy).
4. `key_fallback` → the raw key (inline, marked `[untranslated]`) + an OTel metric + admin counter badge.

Rules:

- Resolution runs at render time (server), never client-side pick — no client-trust rule (AGENTS.md).
- The cache key carries the resolved locale, so edge cache never crosses languages.
- A catalog publish purges the edge cache for that locale (same purge contract as `theme-runtime.md` §edge_cache_and_purge).
- A key that exists in `bn` but not `en` (or vice versa) is a normal state, not an error — each locale is resolved independently against its own fallback chain.

## 4. Data model (additive)

- `locale_keys` (platform): `key, description, list` (catalog source for editor autocomplete + stats).
- `merchant_locales` (tenant): `merchant_id, locale, active, updated_at` — the enable list; `bn` cannot be disabled in v0.
- `translations` (tenant): `merchant_id, locale, key, value, draft_value, status draft|published|archived, updated_by, updated_at` — RLS `merchant_id = auth.uid()` via current_tenant (staff RBAC grants edit per 02).
- No new columns on `pages`/`products`: copy rides catalogs; data fields that are user content (product title) are **not** translated here (a separate scope) — only UI strings are in this spec.

## 5. Editor surfaces (inventory)

1. **Translations page** (`/admin/settings/languages`): locale tabs (bn · en), search box (key + value), filter chips (draft/published/missing), dense table rows: key (mono), current value (Bangla-first preview), **status badge** ( unpublished draft, ✓ published, ⚠ missing).
   - Inline editor row: value edit + `Save` puts `draft_value`, badge flips to `draft`; batch `Publish all` publishes everything saved. Status shown as **text labels** (`unpublished`, `published`, `missing`), never color-only.
   - Bulk row actions: `Publish`, `Revert to theme` (clears override), `Archive`.
2. **Failure surfaces**: a header toast "২টি কী অপরিবর্তিত" (2 keys unpublished) with link to the unpacked list; store preview (`?preview_lang=bn`) shows fallback keys as red-framed rows in the same browser — never silently.
3. **Locked rows**: theme-catalog keys show an `theme` source tag, disabled value field (read-only until override), tooltip "Theme controls this label".

## 6. Plan entitlements + usage meter

Reading `16-product-pricing`, all plans include `bn` + `en`; additional locales and translation-API quotas sit in the GROWTH/BUSINESS tiers only (`entitlement.translation_extended`). The translations page shows the countdown for enabled locales as **text**, not color; over-limit attempts block with `plan_limit_exceeded` (mirror `content-cms.md` §7).

## 7. Design guidelines — translation surfaces

- **Intent**: a component that feels like a "localization deltas" tool, not a dump spreadsheet: value column, per-locale context column, missing rows teal-framed.
- **Key surfaces**: translation page, locale selector, preview bar, batch ops.
- **Palette**: teal for publish; amber for draft; slate for theme-sourced.
- **Typography**: `tab` on key, tabular numerals for counts; noto serif for example quote.
- **Density**: admin-dense, rows 44px; context preview in a right rail.
- **Motion**: no entrance animation; row hover 120ms; snapshot toast 200ms fade (reduced-motion safe).
- **A11y**: table with `aria-label="Translations for {locale}"`; keyboard tab order; focus visible per §3.
- **Anti-slop**: never show bare `JSON` as the value; always a "live buttons" preview.

## 8. Persistence states (per translation row)

| State       | UI                                                    | Note                                                                    |
| ----------- | ----------------------------------------------------- | ----------------------------------------------------------------------- |
| draft       | amber "Draft" chip                                    | saves `draft_value` only                                                |
| published   | mint "Published" chip                                 | visible storefront-locale                                               |
| unpublished | amber "Needs publish" chip                            | `value` empty / draft only                                              |
| error       | coral field border "সংরক্ষণ হয়নি — আবার চেষ্টা করুন" | 409 conflict shows server value and preserves mine (`from server` link) |

## 9. Testing gates

- `store_loop` adds: locale cookie → storefront renders `lang` attribute + chosen copy; publish only `bn` → `en` shows fallback; purge both locales.
- `admin_loop`: override → publish → render swap; revert to theme; plan-limit block; 409-conflict concurrency.
- Failure suite: namespaced missing keys fall to platform EN defaults (never blank); runtime locale crash → fallback template (see `theme-runtime.md`).

## 10. Residual v0 gaps

- Numerals locale (bn digit rendering in product prices) is theme-layer only; core BN-digit formatting flows via `fmtBDT` (see `00-meta`).
- The string is the contract: a key never changes mid-stream; renaming a key is a new key + archive of the old one (archived keys keep history).
- Locale catalogs ride the theme manifest (its files, language list); extra locale catalogs are v1.
- RTL writing systems (Arabic, Urdu) and bidi layout are out of scope; tl;dr — Bangla is LTR, so v0 keeps one direction.
- A third locale beyond `bn | en` is a v0 non-goal: entitlements may record it (§6), but its catalog delivery ships in v1 — any missing key falls back to platform EN (§9).
